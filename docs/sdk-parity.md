## Test parity

All SDKs MUST pass the same `query-vectors.json` set. A parser change in any SDK that fails a vector blocks the merge.

## Verification

Run the full cross-SDK conformance suite locally:

```sh
make parity
```

Or via the script directly:

```sh
./scripts/verify-sdk-parity.sh
```

`make check-all` runs `parity` as part of the pre-merge gate.

## Known semantic gaps

- **`Cost` fields**: py uses `Optional[float] = None` (distinguishes
  absent from `0.0`); ts uses `?: number` (same semantic); rs and php
  use plain `f64` / `float` with `0.0` defaults (`omitempty` on
  serialization handles the wire). Wire-format parity holds.
- **Tristate notation**: `*bool` (Go), `Optional[bool]` (py),
  `boolean | undefined` (ts), `Option<bool>` (rs), `?bool` (php).
  Documented in `aim.go` package comment.
- **ts mixed-case**: `Model` uses snake_case (matches JSON wire),
  `Filter` uses camelCase. New fields follow the same convention.
  This is the only intentional naming asymmetry across SDKs.
